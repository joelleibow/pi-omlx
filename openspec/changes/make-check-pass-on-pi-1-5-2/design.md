# Design

## Context

The repository develops against pi 1.5.2 and type-checks against its own pi-ai, which the lockfile resolves at 0.80.10 while `@earendil-works/pi-coding-agent` 1.5.2 pins pi-ai at exactly 1.5.2 and carries its own copy (`research-chidi.md` §1.1, §1.5; `research-eleanor.md`, "Dependency and TypeScript configuration"). That split is the whole failure: Biome passes and the suite passes, and `tsc --noEmit` reports ten errors in two groups, the version mismatch at `src/provider.ts:35,37` and eight union reads at `test/provider.test.ts:49-53,60,66,72` (`research-eleanor.md`, "HEAD typecheck failures"). Motivation and scope are `proposal.md`'s.

Constraints that shape the approach:

- pi never loads this repository's pi-ai. Its loader maps the root entry and `/compat` to pi's own extension view (`research-chidi.md` §1.2), so tsc is the dev copy's only consumer and the check is green exactly when the dev copy matches the one pi runs.
- The spec fixes the outcomes: one installed pi-ai at pi-coding-agent's pin, the `check` script exiting 0 after `npm ci`, no suppression in tracked code, and a run under a scratch `PI_CODING_AGENT_DIR` writing nothing to the operator's cache file (`specs/verification/spec.md`).
- The suite writes `cache/omlx-models.json` under the agent directory it resolves (`michael-orientation.md` §1, citing `src/catalog.ts:567`), so runs are prefixed (`owner-rulings.md` §3).
- pi's docs keep host packages in `peerDependencies` with `"*"` and out of `dependencies`, and prescribe no devDependency range (`research-chidi.md` §1.4). This change keeps both facts.

## Goals / Non-Goals

**Goals:**

- `PI_CODING_AGENT_DIR=<scratch directory> npm run check` exits 0 on the pi versions the package declares.
- One installed `@earendil-works/pi-ai`, at the version pi-coding-agent pins.
- The type check passes because the code matches pi's declarations, with no new suppression, cast or `any`.
- All three requirements of `specs/verification/spec.md` are satisfied.

**Non-Goals:**

- No runtime behaviour change. The production edit is type annotations (`michael-orientation.md` trap c).
- No dependabot grouping (Michael's orientation call #1; the conductor's scope).
- No removal of pi-ai's compat entry (`michael-orientation.md` trap e).
- No test isolation by default (`owner-rulings.md` §3).
- No edit to `src/provider.ts`, `src/stream-writer.ts`, `src/stream-events.ts` or `index.ts` (`research-eleanor.md`, "Type use and test inputs"; `michael-orientation.md` trap c).
- No project documentation in the implementation diff. The docs pass writes it after the implementation gate.

## Decisions

Each requirement maps to a decision: Requirement 1 to decisions 1 to 6, since the dependency and the two type fixes are what make the type-check half of the script pass; Requirement 2 to decision 5; Requirement 3 to decision 6's prefixed run.

### 1. The pi-ai devDependency moves to `^1.5.2`, and the lockfile comes from a real install

The `@earendil-works/pi-ai` devDependency becomes `^1.5.2`, matching `@earendil-works/pi-coding-agent@^1.5.2`, whose 1.5.2 pins pi-ai exactly (`research-chidi.md` §1.1; `council.md`, agreements). The lockfile is regenerated by running `npm install`, and the regenerated file is committed, because the check has to run against the installed tree and the lock and `node_modules` have to move together.

The install check runs `npm ci` from the committed lockfile, then `npm ls @earendil-works/pi-ai --all`: every copy must report the same version, and that version must equal what `node_modules/@earendil-works/pi-coding-agent/package.json` pins. At HEAD the command reports three paths at two versions, 0.80.10 at the top and 1.5.2 under pi-coding-agent and pi-agent-core; Eleanor's scratch copy reports every path at 1.5.2 (`research-eleanor.md`, "Dependency and TypeScript configuration"; "Scratch bump measurement").

Alternatives:

- **Exact pin `1.5.2`.** Rejected: pi-coding-agent is at a caret, so one caret update to 1.5.3 pins pi-ai 1.5.3 while pi-ai stays at 1.5.2, and the split returns (`council-neil-pass1.md` Q1; `council-matt-pass1.md` Q1; `council-matt-pass3.md`).
- **Drop the pi-ai devDependency and let npm hoist pi-coding-agent's nested copy.** Rejected: it trades an explicit dependency for a phantom one and fails the moment hoisting changes (`michael-orientation.md` §4; `proposal.md`, risks).
- **`npm install --package-lock-only`.** Rejected: it moves the lockfile and leaves `node_modules` holding 0.80.10, so the check would still run against the old copy and the install check would contradict the lock.

The change takes away the second pi-ai copy in the tree, so anything resolving an older pi-ai would stop. Nothing under `src/`, `test/`, `index.ts` or `scripts/` imports one (`research-eleanor.md`, "Type use and test inputs").

### 2. `src/stream.ts` carries the branded context, and `src/repeat-stop.ts` does not

Three annotations change from `Context` to `TranscriptContext`: the import in the type block at `src/stream.ts:1-10`, the internal stream attempt's context parameter, and the public wrapper's context parameter (`michael-orientation.md` trap c, which names `:5`, `:91` and `:185`). The two call sites that fail under the bump, `:126` and `:209`, then receive a value that satisfies the parameter they pass it to (`research-eleanor.md`, "Scratch bump measurement"; `research-chidi.md` §3.2 for the `streamSimple` signature).

There is no runtime change. `TranscriptContext` is `{ messages: Message[] }` plus a type-only brand on a non-exported unique symbol, and `normalizeContext` returns a plain object (`research-chidi.md` §2.1–2.2; `michael-orientation.md` trap c). pi hands the registered `streamSimple` a `TranscriptContext` already (`research-chidi.md` §2.6), and the wrapper forwards that value unchanged and reads it as it does today; `isRepeatStop(event, context)` at `src/stream.ts:143` still accepts it, because a `TranscriptContext` assigns to a `Context` (`research-eleanor.md`, Addendum 1; `michael-orientation.md` trap c).

`src/repeat-stop.ts` keeps `Context`. It raises no error today, nothing under `test/` calls it directly (`research-eleanor.md`, Addendum 1), and the assignability means the brand never has to reach the repeat-stop logic (`council.md`, agreements; Neil pass 1 Q4, Matt pass 1 Q4).

Alternatives:

- **Cast at `:126` and `:209`.** Rejected: a cast in place of the fix, which decision 5's diff check exists to catch (`michael-orientation.md` trap b).
- **Call `normalizeContext` inside the wrapper.** Rejected: pi normalized the context before calling in (`research-chidi.md` §2.6), so a second call is a no-op that copies pi's rule into this repository.
- **Retype `src/repeat-stop.ts` too.** Rejected: structure with no behaviour behind it, spreading the brand through logic that never touches provider code (`council.md`, agreements).

### 3. Every context the stream test hands the wrapper comes from `normalizeContext`

`EMPTY_CONTEXT` at `test/stream.test.ts:123` becomes `normalizeContext({ messages: [] })`, annotated `TranscriptContext`; the `context` in the repeat-stop test, at `:293`, becomes `normalizeContext({ messages: [priorAssistant] })`, annotated the same way. `normalizeContext` is imported from pi-ai's root entry, where it sits alongside the `TranscriptContext` type (`research-chidi.md` §2.2–2.3).

Both fixtures reach the wrapper's context parameter, and the calls to `streamOmlxOpenAICompletions` in the file are `:193`, `:217`, `:239`, `:267`, `:307`, `:324` and `:347`, so once decision 2 brands that parameter an unnormalized `Context` is TS2741 (`council-neil-pass2.md` M2; `council-matt-pass2.md` N3; `research-eleanor.md`, Addendum 1). Those lines are Michael's reading of source at `c4d51ff`, which overrides the `:111` and `:298` in `research-eleanor.md`. The mock's signature and the context it records stay `Context` (`test/stream.test.ts:12-24`): a `TranscriptContext` assigns to a `Context`, and tsc forces only the calls that receive the two fixtures, not the mock's signature (`council-matt-pass1.md` Q3; `michael-orientation.md` trap c).

The annotation is explicit rather than inferred. Annotating `TranscriptContext` keeps the brand at the call site and makes a later edit that swaps the initializer for a literal fail at compile time, which is the failure Michael reproduced when he left a `{ messages: [priorAssistant] }` literal typed as `TranscriptContext` (`michael-orientation.md` trap c).

Alternatives:

- **Cast the fixtures, or build them as literals with an assertion.** Rejected: `normalizeContext` is the only producer of the type (`research-chidi.md` §2.2), and a cast is what decision 5 forbids.
- **Retype the mock to `TranscriptContext`.** Rejected: tsc does not require it, and it changes structure with no behaviour attached (`council-matt-pass1.md` Q3).

### 4. `test/provider.test.ts` gets one throwing `chatModel` helper with the positive predicate

```ts
function chatModel(m: ProviderModelConfig | undefined) {
	if (m === undefined) throw new Error("no model entry");
	if (m.type !== undefined && m.type !== "chat") throw new Error(`not a chat model: ${m.type}`);
	return m;
}
```

The predicate is Michael's ruling: throw on `undefined`, throw unless `type` is undefined or `"chat"`, return `m` (`council.md`, "Michael's Rulings"). The eight reads at `test/provider.test.ts:49-53,60,66,72` go through it, so the empty-model case fails loudly rather than reading a field off `undefined`.

It narrows because `type` is optional on the chat member alone and required on the image and classifier members, so the check leaves exactly the chat member (`research-chidi.md` §4.2, citing `types.d.ts:1530-1531`). `ProviderChatModelConfig` is not re-exported from `pi-coding-agent/dist/index.d.ts:8`, so the helper's return type is inferred and the predicate is the only control over it.

The mutation is how the helper proves it does not weaken the assertions: set the condition at `src/provider.ts:61` to `thinkingDefault !== false` in a scratch edit, run `PI_CODING_AGENT_DIR=<scratch directory> npx vitest run test/provider.test.ts`, watch it fail, then revert. Michael ran this with the positive predicate, under the isolated agent dir: `tsc --noEmit` 0 errors, the provider test 4/4, mutation 1 failed (`council.md`, "Michael's Rulings"; `michael-orientation.md` trap b).

Alternatives:

- **An inline guard around each assertion.** Rejected: when the entry is not chat the guard skips the assertion and the test stays green with the check deleted (`council-matt-pass1.md` Q2).
- **The negative form, which throws when `type` is `"image"` or `"classifier"`.** Rejected by Michael's ruling: it enumerates the complement of a set pi owns, reddening `tsc` on a bare fourth member and letting a rich one through as chat.
- **`isModelType()`.** Rejected: a `ProviderModelConfig` is not an `AnyModel`, and the call is TS2345 (`research-chidi.md`, Addendum 1; `council.md`, agreements).
- **No helper, eight casts.** Rejected: a cast in place of the fix, and the fifth read is the second repeat (`council-neil-pass1.md` Q2).

### 5. Two checks live on the diff, not in the living spec

- **No new cast or `any`.** The check reads the change's diff for `as unknown as`, `as any` and `: any`, and confirms the six pre-existing casts are untouched: `src/stream.ts:125,208` in production, and `test/stream.test.ts:93`, `test/oauth-login.test.ts:92`, `test/provider.test.ts:94` and `test/index.test.ts:61` in tests (`michael-orientation.md` trap b). It is here because the spec's grep cannot see a cast: copying `test/provider.test.ts:94`'s `as unknown as Record<string, unknown>` onto the four assertions would pass both the check and the grep (`council-matt-pass1.md`; `council-neil-pass2.md` M4).
- **The suppression grep's baseline.** Run `git grep -nE '@ts-ignore|@ts-expect-error|@ts-nocheck|biome-ignore' -- ':!*.md'` at HEAD and again at the end, and record both. Michael's baseline counted three of those four patterns, so the first run is what establishes `@ts-nocheck` (`council-matt-pass2.md` N1). If the first run is red, work stops and the conductor is asked: the requirement admits no suppression, and removing one this change did not add is a scope decision rather than a mechanism choice.

Alternatives:

- **Put the no-cast rule in the living spec.** Rejected: it would be false the day it landed, because the pre-existing casts stay (`council-neil-pass1.md`, challenge 1; `council-matt-pass1.md`, finding 1).
- **Trust the grep alone.** Rejected: it cannot distinguish a new cast from a pre-existing one.

### 6. Order of work: the dependency first, then types, with the error count as each step's check

Nothing here changes at runtime. Joel's rule is to make the change easy and then make the easy change, and in this change it shows up as ordering by what unblocks what, with each step carrying its own evidence. Four steps, four commits.

Every `vitest` and `npm run check` command below carries `PI_CODING_AGENT_DIR=<scratch directory>`, because Joel ruled that no run of the suite writes his real agent directory, and Requirement 3 covers any part of the check (`owner-rulings.md` §3; `specs/verification/spec.md`).

1. **The dependency and the lockfile.** `package.json` and `package-lock.json`, nothing else. Check: `npm ci`, then `npm ls @earendil-works/pi-ai --all` reports one version at pi-coding-agent's pin, and `npx tsc --noEmit 2>&1 | rg -c 'error TS'` prints 10, the total HEAD prints too, with the two `src/provider.ts` errors replaced by two TS2741 at `src/stream.ts:126,209` and the eight TS2339 in `test/provider.test.ts` untouched (Michael's PL7 measurement in the scratch, pi-ai `^1.5.2` deduped; `research-eleanor.md`'s "nine errors remain" and `michael-orientation.md` §2's "exactly 9 errors" both miscount). This step cannot be reordered later: 0.80.10 exports no `TranscriptContext` and no `normalizeContext` (`research-chidi.md` §1.5), so no annotation or fixture can be written against it.
2. **`src/stream.ts`'s three annotations and the two `test/stream.test.ts` fixtures, in one step.** The annotations brand the wrapper's parameter and red both test call sites until the fixtures are wrapped, so half a step leaves the count higher than either end. Check: `npx tsc --noEmit` reports no TS2741, and every remaining error is TS2339 in `test/provider.test.ts`; `PI_CODING_AGENT_DIR=<scratch directory> npx vitest run test/stream.test.ts` is green.
3. **The `chatModel` helper and the eight reads.** Check: `npx tsc --noEmit` reports 0; `PI_CODING_AGENT_DIR=<scratch directory> npx vitest run test/provider.test.ts` passes 4/4; the `thinkingDefault` mutation, run the same way, fails the test and is reverted.
4. **The whole check.** Check: `PI_CODING_AGENT_DIR=<scratch directory> npm run check` exits 0, Biome clean and the suite at HEAD's counts, 11 files and 84 tests (`research-eleanor.md`, "Check command and HEAD verification"). Around that run the task reads content, not clocks. Joel's `~/.pi/agent/cache/omlx-models.json` is recorded before and after by its `apiRoot` and model ids, or as absent, and afterwards it holds none of the fixture's values. The scratch directory's own `cache/omlx-models.json` holds the fixture `apiRoot` with a `savedAt` no earlier than the run's start, which is what proves this run's write landed there. Content is the discriminant because the two writers write different roots. The suite writes the fixture root that `test/index.test.ts:72,76` registers, and a live session rewrites the file from its own `apiRoot` on a ten-minute poll (`index.ts:34,115,301`). `src/catalog.ts:596-600` writes the whole file with one `apiRoot`, so a test write into Joel's file would replace its root with the fixture's. Michael measured that premise at PL7, both files' content and those code paths; timing is why an mtime check reddens with no test at fault. The two diff checks from decision 5 run in this step as well.

Alternatives:

- **Land the type changes and the dependency bump in one commit.** Rejected: the bump's evidence is the two provider errors going and two stream errors arriving, and a single commit cannot show both.
- **Do the provider test first.** Rejected: it is independent of the bump, and doing it first hides the count that proves the bump did what the scratch predicted.

### 7. The implementation diff carries no project Markdown, and the docs pass adds one isolation note

The diff is `package.json`, `package-lock.json`, `src/stream.ts` and the two test files. The change's own artifacts under `openspec/changes/`, `tasks.md` included, are planning records rather than project documentation, and Michael's rule about a Markdown file in the diff is about project documentation (`michael-orientation.md` §1). The docs pass, after the implementation gate, greps tracked Markdown for `0.80` and `pi-ai` and finds nothing, so no existing sentence went false: `README.md` and `CONTRIBUTING.md` name the check without naming a pi version.

It also adds a paragraph to `CONTRIBUTING.md`'s Setup section, because that section tells a contributor to run the suite bare while Joel's ruling and Requirement 3 make a scratch `PI_CODING_AGENT_DIR` the condition of any run (`owner-rulings.md` §3; `specs/verification/spec.md`). The paragraph says what a bare run costs, that it replaces the contributor's cached model list with test fixtures, and names the variable to set. An empty scratch directory is enough, because `src/catalog.ts:598` creates `cache/` under it. The paragraph goes when the suite isolates itself.

## Risks / Trade-offs

- **[Risk]** Nothing in the repository ties the two caret ranges together, and `.github/dependabot.yml` groups nothing, so a per-package update re-splits the versions. **[Mitigation]** tsc is the detector: the split surfaces as the two `src/provider.ts` errors. Grouping is declined on the conductor's scope, and the check going red is the signal Joel asked for (`michael-orientation.md` trap a and §4; `proposal.md`).
- **[Risk]** `npm ci` reproducing the deduped single-version tree is unverified, since the scratch measurement used `npm install` (`council-matt-pass1.md`, Assumptions). **[Mitigation]** step 1 runs `npm ci` before `npm ls`, so the assumption becomes a measurement; a second version at that point stops the change rather than passing quietly.
- **[Risk]** The operator's cache file changes during a run for a reason unrelated to the suite: a live session rewrites it on a ten-minute poll (`index.ts:34,115,301`), so a check on its modification time goes red with no test at fault. **[Mitigation]** the check reads what was written, not when. Joel's file afterwards carries no fixture `apiRoot` or model id, and the scratch file's `savedAt` falls inside the run window (`design.md`, decision 6 step 4).
- **[Risk]** The suppression grep may be red at HEAD on `@ts-nocheck`, which nobody counted. **[Mitigation]** the baseline runs before any edit, and a red baseline goes to the conductor (decision 5).
- **[Risk]** The green check is the only guarantee this change buys, because the production edit changes no behaviour. **[Mitigation]** accepted deliberately. When the copies split, `tsc` says so at `src/provider.ts:35,37`, which is the "something is wrong and we know what" Joel objected to losing (`michael-orientation.md` §4).
- **[Trade-off]** `chatModel` turns a compile-time field read into a runtime throw. **[Accepted]** that is the point: a fixture that is not a chat entry fails loudly instead of skipping an assertion (`council-matt-pass1.md` Q2).
- **[Trade-off]** The helper's return type is inferred rather than named, because `ProviderChatModelConfig` is not exported. **[Accepted]** the predicate is the only control over the inferred type, which is why Michael's ruling fixed its form (`council.md`, "Michael's Rulings").
- **[Risk]** No logging, health check or flag is added. **[Mitigation]** nothing at runtime changes, and no use case, adapter or entry point is added, so the check is the observable and its exit status is the signal.

## Migration Plan

Nothing is deployed and no state is written. The change is a repository property, and its rollout is the four commits of decision 6, each revertible on its own: the type steps revert to the previous error count, and step 1 reverts the manifest and the lockfile together.

Rollback is `git revert` of those commits. `node_modules` returns with `npm ci` from the previous lockfile. No file under `~/.pi/agent` is written by design, and the prefixed runs are what keep that true (`owner-rulings.md` §3). No flag, no staged release and no cache migration applies, because the extension's behaviour, provider id and public surface do not move.

## Open Questions

None that change this design. Chidi did not test whether pi always releases pi-ai and pi-coding-agent in lockstep (`council-neil-pass1.md`, "What would change my mind"); if they ever part, the split surfaces as the two `src/provider.ts` errors and the mechanism here is unaffected. Removal of the compat entry that `src/stream.ts:23` uses is a future change (`michael-orientation.md` trap e).
