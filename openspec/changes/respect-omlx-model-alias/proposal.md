# Proposal

## Why

OMLX lets each model carry an alias and treats that alias as the model's API-visible name: `/v1/models` lists the alias in place of the directory name, and requests accept either value (`research-chidi.md` §2). `pi-omlx` ignores the field, so `/model <alias>` and `settings.json`'s `defaultModel: "<alias>"` never reach the model. That is the behavior Joel reported on 2026-11-22 (`owner-rulings.md`).

A display-only fix cannot close it. Pi compares only `model.id` on both paths the bug names — `/model <arg>` through `findExactModelReferenceMatch`, ignoring case, and `defaultModel` through `getModel`, byte-for-byte — and never consults `name` (`research-chidi.md` §1.2; `michael-orientation.md` P1). The extension publishes the endpoint's id as Pi's `id` and sets only `name` (`research-eleanor.md`, "Pi model mapping and refresh/storage"), so an alias that arrives as a label resolves on neither path (`michael-orientation.md` T1).

A second defect sits in the same flow. When the status endpoint cannot be read, the `/models` fallback already publishes alias ids while the local overlay is matched by raw id, so every aliased model silently loses its overlay — measured at a context window of 32768 instead of 131072 (`michael-orientation.md` T2). A documented setup hits this path (`docs/CONFIGURATION.md:57`).

## What Changes

- **An aliased model is published under its alias.** When the server gives a model an alias that no other entry on the status endpoint carries, ignoring case, as its folder name or alias, the alias becomes the model's Pi `id`, so `/model <alias>` and a saved default of the alias resolve. The published alias comes from the server, never from the overlay (`michael-orientation.md` T3, §5.1–§5.2; `council.md` R6).
- **The raw folder name stays the display label where OMLX sets no display name.** Pi's `name` remains OMLX's `display_name` when it is set, and the raw folder name otherwise — alias or not. The label is the only text Pi searches beyond the id, so the old name stays findable in the picker exactly where the folder name is the label, meaning `display_name` is unset (`michael-orientation.md` §4 Option 1, T4; `council.md` R5).
- **Both endpoints publish one set of ids.** The status path takes `model_alias`; the `/models` fallback already returns the alias as its id, so for every model both endpoints list whose alias the status path accepts, the two publish the same id and a failed status request no longer flips ids back and forth (`michael-orientation.md` T2; `council.md` R3). On the fallback the published id is always the value `/models` returned: exact duplicate ids collapse to the first, first kept, and ids that differ only by case publish as reported, each traced (`council.md` R3, R11).
- **The overlay is matched by folder name on both endpoints.** On the status path the match is the exact directory-name key, as today. On the fallback path the folder name is recovered from the overlay, in order: a key equal to the `/models` id, then the single entry whose `model_alias` equals that id byte-for-byte; two or more alias matches apply no overlay fields and name the competing keys in a trace (`michael-orientation.md` §5.3, T2; `council.md` R4). A match applies the overlay entry's fields and never the published id.
- **A collision falls back to the folder name.** On the status path an alias is published only when it does not equal, ignoring case, another parsed entry's endpoint id or alias — so a duplicate alias, an alias equal to another model's folder name exactly or by case, and an alias equal to an exposed-profile id all publish under the folder name. The identity step drops only exact duplicate ids, first kept, as the parsers did before, so the refresh publishes, and the login probe counts, the same models as before; no refresh fails because of a collision, and the decision is traced (`michael-orientation.md` T6, §5.4; `council.md` R3, R6).
- **An unset alias is no alias; every other alias is verbatim.** A `model_alias` that is absent, `null`, not a string, or `""` is unset. Every other string, whitespace-only and padded values included, is published byte-for-byte when the collision rule accepts it, untrimmed and case-preserved, because OMLX advertises and routes exactly what it stores (`council.md` R7; `research-chidi.md` §2).
- **BREAKING — saved references written under a folder name stop resolving until they are re-saved.** After the first refresh that publishes aliases, a `defaultModel`, a session record, a `modelThinkingLevels` key, a glob `enabledModels` entry naming the folder, or a `models.json` `modelOverrides` key written under the folder name stops resolving; Pi falls through to another provider's default and session restore reports a miss (`research-chidi.md` §1.3; `michael-orientation.md` T9). A folder-name `defaultModel` misses on every start until the alias is saved as the default with `Ctrl+S` on the alias row in `/model`, or by editing `settings.json`; `/model <alias>` and pressing Enter in the picker switch only the session (`owner-rulings.md`, 2026-11-22; `council.md` R1–R2). Non-glob `enabledModels` patterns and `--model <folder name>` keep resolving through the label while the label is the folder name, because those paths match `name` fuzzily (`research-chidi.md` §1.2; `council.md` R2). Joel accepted this cost with Option 1. Nothing in Pi's files is migrated (D7).
- **A session that outlives the id re-key keeps honoring `off`.** Pi keeps a session's stale model object when its id leaves the list, so `index.ts`'s `before_provider_request` hook stops finding the model and stops writing the thinking controls. Under the existing `omlx` guard, a list miss at Pi's thinking level `off` now applies those controls; at any other level the payload is left alone and no stale `reasoning` is read (`michael-orientation.md` T8; `council.md` R8).
- **The identity and overlay decisions are visible on stderr.** One `onDebug` identity event per fetch records each kept entry's endpoint id, directory name, alias, published id and any decline reason, plus the duplicate ids the identity step collapsed and the published ids that differ only by case. Each overlay match's outcome is recorded, and the applied-settings trace carries both names (`michael-orientation.md` T11; `council.md` R11). All of it rides the existing `PI_OMLX_DEBUG` predicate and `[pi-omlx]` prefix.
- **Deliberately not in this change:**
  - No second registration per model — no Pi virtual model, no duplicate entry, no doubled picker. Option 1 rules out Option 3's shape (`michael-orientation.md` §4, T12).
  - No migration or rewriting of Pi's `settings.json`, session records, `models.json` or `models-store.json`, and no re-keying in the offline phase: it keeps publishing exactly what Pi stored (`catalog-discovery`, "A start reads the store, not a cache of the extension's"; D7).
  - No new startup warning for a default that no longer matches. The at-most-one-warning rule stands (`catalog-discovery`, "A Session Start Warns At Most Once About The Model It Landed On"; D4), and detecting the case would mean copying Pi's settings merge (T9).
  - No `setModel` and no re-run of Pi's starting-model selection (D5).
  - No change to credential resolution or Pi's `check`/`resolve` hooks (ADR 0002), to the single registrable rule or what `/login omlx` counts (D6), to limit precedence, to the status-first fetch order, to hidden-model handling, or to exposed-profile overlay lookup.
  - No new fetch, timer or startup work: the rule runs inside the refresh hook (`catalog-discovery`, "Pi's Refresh Decides When The Catalog Is Fetched"; D2).
  - The one-start lag after an upgrade or alias rename is accepted, not fixed (D3; `michael-orientation.md` T10).
  - No module restructure of `src/catalog.ts`: the identity rule lands in the module that already owns OMLX-to-Pi translation, and the restructure Joel plans to lead stays out of scope (`council.md` R9; D8).
- **Settled, not open.** The council settled module placement and vocabulary, the outliving-session question and which name each event carries (`council.md` R8–R11); Joel settled the saved-default cost with Option 1 (`council.md` R1). `council.md` and `design.md` hold the rulings and the mechanism; this proposal states scope only.

## Capabilities

### New Capabilities

None. The behavior belongs to an existing capability.

### Modified Capabilities

- `catalog-discovery`: a catalog entry's published id, display label, overlay lookup and collision fallback follow OMLX's alias contract, and both endpoints publish the same ids. The requirements are added to this capability rather than changing an existing one: no current requirement states how the extension maps an endpoint entry to a Pi model's `id` and `name`. Diagnostics gain content, not a new switch — the identity event, the overlay match outcome and the two-name applied-settings trace all ride the existing `PI_OMLX_DEBUG` predicate under the existing `[pi-omlx]` prefix, so the `diagnostics` capability's predicate and prefix requirements are unchanged (`council.md` R11).

## Impact

- **Code.** `src/catalog.ts`: the status parse, the `/models` parse, the post-parse overlay and defaults pipeline, the Pi model mapping, and the traces that name a model — including one module-private identity function that owns how the published id is chosen (`council.md` R9). `index.ts`: the `before_provider_request` hook's list-miss branch for a stale session model at level `off` (`council.md` R8). `src/login.ts` reads the same `fetchModels` and `registrableModels` and must keep its count (D6). `src/provider.ts` and the stream modules keep working against one id per model.
- **Tests.** `test/catalog.test.ts`, `test/refresh.test.ts` and `test/index.test.ts` carry the behavior. The existing `vision-lane` fixture pairs an overlay entry keyed by folder name with `model_alias: "vision"` and asserts only display name, limits, thinking, parser and type (`research-eleanor.md`, "Tests and assumptions"; `michael-orientation.md` T13): it becomes the acceptance case for the overlay rule and must either hold unchanged or change on purpose. New tests write their overlay under `inject("isolationRoot")` with no new `process.env` key (D9). Pi's own resolution is proven by asserting the published and persisted `id`, never by a test that imports Pi's resolver (`council.md` R12).
- **APIs and dependencies.** No public API and no dependency change. Pi 1.5.2 and 1.6.0 match models the same way on these paths (`research-chidi.md`).
- **Wire behavior.** The request carries the published id verbatim, and OMLX accepts an alias or a folder name there, so either published value routes (`research-chidi.md` §2; `michael-orientation.md` §5.9).
- **Documentation.** Updated in this change's docs pass, listed in `design.md`'s Migration Plan (`council.md` R15).
- **Before acceptance, Joel.** He watches it work on his own server; the checks are `tasks.md` 7.3 (`council.md` R12; `~/Projects/AGENTS.md`, "Nothing is done on an application change until Joel has watched it work").
